# 素材取得與真實性

## 素材優先序

1. 使用者已指定且允許公開的實拍、筆記、白板與產品畫面。先讀回實體檔，檢查有無私人資訊。
2. 有明確用途與使用條件的官方素材、產品介面或書封。記下原始頁面、取得日期和使用條件；不能看到圖片就標「已授權」。
3. 確認可用的授權圖庫或公共領域素材，保存作者、來源與授權依據。需要署名時納入成品。
4. 沒有合適原件時，交自攝／截圖清單；若使用者接受生成示意，可用 imagegen 並標明生成性質。

研究作者的輪播是設計參考。不要把其中的照片、書封截塊、人像或品牌圖搬進自己的發布稿；需要同類素材時回到原始來源另行取得。

## 每個素材都需要的帳本欄位

`asset_id / 類型 / 圖片用途 / 原始來源 URL 或絕對路徑 / 作者或權利人 / 取得日期 / 使用條件與依據 / 可公開範圍 / 真實性狀態 / 處理方式 / 使用頁碼 / 本地檔案 / 待補事項`

真實性狀態分開寫：`verified_original`（原件已讀）、`official_asset`（來源已查）、`generated_illustration`、`reference_only`、`pending`。前兩者仍需獨立確認可發布範圍。沒打開過的照片不能標 `verified_original`。

`source_of_claim` 與 `source_of_image` 分開：桌面照片能說明工作情境，不能證明「效率提升三倍」。原文中的日期、產品能力或數字需要時效查證；研究作者的敘述不自動變成已查證事實。

## 找圖／取圖要具體

先列需求，再依需要查找，不先下載一堆泛用圖。依使用者環境可用的搜尋工具找來源頁，圖片內容與完整輪播仍需直接查看原頁／原圖。不要以搜尋摘要代替視覺分析。

例：要解釋「資料有沒有整理」可規劃同一桌面、同一光線下的散開便條與分好類的便條；不是搜尋「AI productivity futuristic」。查到候選原頁後核對實際圖片、尺寸與條件，再保存。

對瀏覽器來源，使用已載入頁面的素材匯出能力或可用 connector，核對圖卡順序，排除頭像、留言圖、推薦貼文及追蹤像素。逐頁看至末頁，再讀回檔案數、尺寸與校驗值；保存來源連結與頁碼。登入、限流或圖片讀不到時如實記錄，不繞過存取限制。

## 自攝清單格式

| 素材 ID | 拍什麼 | 鏡位／光線 | 要表達的關係 | 留字區 | 排除項目 | 狀態 |
|---|---|---|---|---|---|---|
| A01 | 同一張桌面上的三組便條 | 俯拍、窗邊柔光 | 三組素材對應三個內容分類 | 上方約三分之一乾淨桌面 | 真實客戶姓名、手機通知 | 待拍 |

這是拍攝指令示例，不是已存在的照片，也不是使用者的真實工作經歷。

## 圖片處理與保存

- 保存原件；修改使用新檔名，不覆寫來源。輸出記錄原件、處理指令、工具與成品。
- 圖片編輯遵守目前 imagegen／工具規則，實際提供所需參考圖。不能只寫「沿用 screenshot.png」卻沒傳入檔案。
- 若需要原畫面一字不變，原圖作獨立排版層，生成視覺作另一層；生成的假截圖不能替代原圖。沒有可保留原件的製作工具就回報這項限制，不自行放寬需求。
- 禁止更改真實紀錄的數字、時間、使用者身份或產品內容來湊故事；教學模擬介面要清楚標「示意」。
- 研究目錄和發布目錄分開；內部使用條件與競品分析不印進對外成品，必要的公開署名則保留。
