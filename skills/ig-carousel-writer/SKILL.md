# IG 輪播圖文

先決定讀者要理解什麼，再讓素材承擔解釋工作。預設採「真實世界素材＋清楚標註」的教學方向，依題材穿插簡潔文字頁。產物存回使用者指定或目前專案的正式位置。先讀 `references/寫作與事實規則.md`。

## 本人直接分享（一魚多吃）

把作者自己的影片、口述或文章改編到另一平台時，說話的人仍是作者本人。讀者不需要看過來源，就能理解這篇內容。

- 正文直接表達觀點、建議與有依據的經歷。不要用「我在影片裡提過」「影片裡的做法」「作者在影片中分享」「這篇是依影片整理」介紹自己的內容，也不要只是換成「我曾經說過」來保留轉述框架。
- 例如「我喜歡用一個在影片裡分享過的拆法」可改成「我認為最好的方法是……」；「影片裡提到可以固定聚餐」改成「我的建議是，固定安排聚餐」。依語意自然選擇「我認為」「我的做法是」「我會建議」或直接說明，不強制每句加「我」。
- 改口吻不能創造事實：有實作依據才寫「我的做法」，建議仍是建議；不把他人的經歷變成自己的，不憑空增加長期習慣、成果、原創歸屬或保證。「我認為最好」可表達作者立場，不自動擴張成客觀最佳。
- 書籍、研究、他人方法仍保留必要署名或引用。作者自己的來源網址、逐字稿、時碼及改編紀錄放在內部來源／審查備註；公開正文獨立完整。確有導流目的時，可在結尾保留一次「看完整影片」CTA。
- 交付前逐段檢查「影片裡／影片中／片中／曾提過／依影片整理」及第三人稱介紹作者的句子；依上下文改寫，不機械刪字。原始逐字稿、明確引文、他人內容分析與內部剪輯時碼不受此改寫規則影響。

## 1. 讀來源與品牌

- 讀最近的 AGENTS.md、指定主稿及現有品牌文件；已提供的資訊不用重問。若來源是已發布內容，要核對實際發布版本，不能用本地草稿冒充。
- 確認主題、對象、讀者看完能做的一件事。文案只使用主稿中可確認的主張；照片不能替沒有來源的案例、成果或經歷背書。
- 讀 `references/品牌設定模板.md`。已有品牌設定就沿用。缺配色時可用白底、近黑字作暫定方向繼續；未知帳號、頭像、Logo 不捏造、不硬塞占位頭像。
- 使用者只要文案／規劃時，交付文字與素材表即可，不生圖、不建立 HTML。沒有圖仍能完成規劃，將缺件列入拍攝清單。

## 2. 決定素材與視覺邏輯

先讀 `references/real-world-assets.md` 與 `references/design-system.md`。指定視覺參考時，先查看使用者提供的原圖；只學閱讀動線與資訊層級，不挪用素材、署名或框架。

1. 用一句話寫本套核心訊息，選一個讀者熟悉的物件、情境或介面來解釋它。
2. 將素材分成：可發布原件、只供研究、待確認、生成示意。公開可見不等於可重用；寫實外觀不等於實拍。
3. 每頁寫下圖片的作用：解釋關係、提供證據、定位操作、建立比喻、比較差異或展示資源。回答不出作用就刪掉裝飾圖。
4. 對比同一件事時保持構圖、裁切與標籤位置；解釋步驟時沿用同一場景逐步加註。不要為了變化而每頁換風格。
5. 只有來源與畫面支持時才使用真實截圖、書封或照片；找不到就列出具體自攝／取圖需求，不虛構下載成功。

## 3. 寫逐頁文案與分鏡

依 `references/output-template.md` 保存文案、素材帳本與製作規格。預設 5–10 頁；內容需要且平台當前上限允許時可增加，不把來源的 16 頁案例當成平台規格。主稿太短就做較短輪播，不灌水。

- 開場可用具體問題、直接對照、物件比喻或一句主張，不必一律「痛點 → 金句 → CTA」。
- 每頁一個重點。標題約 8–20 個中文字、內文約 30–80 字是編輯起點，不以字數犧牲必要脈絡；超載先拆頁。
- 素材主導頁讓讀者先認出物件／介面，再讀標註與結論；純文字頁以標題、說明、例子建立層級。
- 不必每頁放頭像、Tweet Card、框線或金句盒；必要文字不可裁切。留白用來分組與停頓。
- 繁中、台灣自然說法；不挪用他人的第一人稱故事、專屬框架、免費資源承諾或留言私訊漏斗。引用別人的方法要署名。
- Caption 補充使用情境、必要來源與一個合適行動。不要逐句強制換行，不強加 Emoji、hashtag 數量或追蹤要求；CTA 只連到真實存在且可交付的資源。

## 4. 製作圖片

- 預設最終規格 1080 × 1350（4:5）；使用者指定比例優先。先做代表頁再延伸整套，依序完成。
- 需要生成／編輯 raster 圖時，載入 imagegen，若環境沒有 imagegen skill，使用當前可用且經授權的圖片工具；依工具支援的參考圖方式，先查看本地原圖，再把實際圖片傳入；不可只在 prompt 提檔名。清楚標明哪張是編輯目標、插入素材、風格參考。
- 原照片、截圖、Logo 的真實內容是保留項。對要求精確不變的介面文字、數字與 Logo，不承諾生成工具能逐像素保留；先生成獨立視覺層，將原件保留於可編輯排版層，使用可用排版工具。需要其他 raster 編輯方式時依當前工具規則及使用者授權處理。
- 不強制每張原始素材重生成；不把生成圖片叫作實拍，不把介面示意叫作產品截圖。私密素材外送前確認授權。
- Logo 使用作者指定且有權使用的原件。用生成／編輯工具時實際傳入，不重畫、不換版本；檔案不可讀時回報缺件。不預載講師 Logo 或個人頭像。
- 不預設 HTML 截圖成品。使用者明確要 HTML 或可編輯網頁時才走 HTML；內容流程的輸出要求優先。工具缺失時交可用規劃、缺件與未完成範圍，不把分鏡稱為 PNG 已完成。
- 精確逐字校對繁中文字；錯字先修正再重看。保留原稿、素材、prompt／編輯指令與選定輸出。

## 5. 視覺與交付驗收

逐張打開輸出，並以全套 contact sheet 看節奏；只做規劃時僅檢查文案／分鏡，不宣稱視覺成品通過。

- 在約 360px 寬的手機預覽中，標題、主要說明和必要截圖資訊可讀；需要讀的細節太小就裁出局部並保留上下文。
- 必要文字不越界，圖片不變形，素材不被重蒙版遮住；箭頭有明確起終點，標籤沒有指錯物件。
- 同一顏色與符號全套語意一致；不只靠顏色區分，搭配文字。
- 原始介面數字、人物、產品、Logo、來源與內容主張讀回一致。研究圖片未混進可發布資料夾。
- 逐頁素材作用明確；需要真實素材的頁面確有原件，或在規劃中標示待補，不以泛用 AI 背景充數。
- 逐頁文案與 Caption 都是作者直接分享，沒有轉述自己來源的口吻；內部素材／製作備註不混入公開內容。
- Caption 無虛構 CTA；檔名、頁數、比例、順序、版本與缺件已核對。

最後提供輸出位置、實際完成項目與待補項目。附代表圖／contact sheet 方便查看；未發布就不要宣稱已發布。
